# Shared intake review

Collection, student confirmation and teacher reading use the existing record with four sections defined in `src/intakeReviewContract.ts`: work and progress; checks and evidence; difficulties and support; next step. No new persisted record schema or SQL migration is required.

The model receives the shared section definitions and explicit close guidance. A vague first reply should receive one focused clarification at a time, normally taking 3–5 student replies. Specific first answers may close earlier. No progress, no tests, no artifacts, undecided plans, support needs, inability to clarify and refusal remain legitimate states. Unknown facts are not invented or made into mandatory student form fields. Future-only plans belong in nextStep rather than progress claims. Hard question limits and teacher judgement remain unchanged. Dialogue revision is intake-dialogue.v1.4; the manifest includes intake-review.v2.

The student wizard always exposes checks/evidence, including unknown status, and optionally adds difficulties/support. It stays within five steps including confirmation. Saved student and teacher views render the same IntakeReviewDetails component, with explicit unknowns, all tests, dependencies and intended next result. Source conversation and correction history remain available to the teacher. The student still confirms an editable summary; the review page is not a substitute for clarification in conversation.

Debug records review_readiness and sparse_review_exit as O observations only. A sparse exit can be premature or a valid bounded/support/refusal exit; the flag is not a verdict and does not override routing. Legacy traces do not have the new manifest version. The persisted stop_reason enum is unchanged for database compatibility: sufficient_information remains a legacy model-review category, not an independently verified completeness verdict. Assessment/gaps and the sidecar supply the more precise interpretation.

The real intake_1.json example is preserved in tests/ai-session-intake/fixtures/s7-sparse-review.json with source SHA256 and its original event/conversation/record. Frozen replay verifies extraction preservation and observation behavior, not whether a newly prompted model will ask better questions. No paid calls were made. New live dialogue quality still requires a fresh acceptance conversation; existing old examples need not be rerun manually.
