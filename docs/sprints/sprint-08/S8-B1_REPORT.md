## 4. The replay runner (item 4)

- Files: `tests/ai-session-intake/replay/run-replay.mjs` (runner),
  `gold-s9.json` (gold), `replay-negative-control.test.mjs` (discrimination
  tests), `out/replay-result-s9.json` (exported result).
- Uses the **real** compiled interfaces `decideTurn` / `validateCandidates` /
  `fallbackQuestion` / `applyEvidenceUpdates` from `src/intakeHarness.ts` +
  `src/intakePolicy.ts`. It feeds each recorded turn's raw candidate through the
  validator and chains the resulting answers turn-by-turn (matching how
  `src/main.tsx` calls it), producing the **actual** accepted evidence — it does
  **not** compare the fixture's stored output with itself. Evidence that the
  output is computed, not echoed: the runner-derived state includes
  `blockerStatus:"active"` (derived by `applyEvidenceUpdates` from a
  `student_claim` blocker update) and the turn-3 fallback question
  `"What one feasible step will you take before the next Session?"` (generated by
  `fallbackQuestion` from the accumulated answers).
- **Intermediate vs. final:** the turn-3 provider failure is rendered as a
  `provider_fallback_snapshot` with `isFinalConfirmedRecord: false`. The runner
  does not invent a final confirmed record for the failed turn.
- **R + state checks only; C/S = N/A** (fixed transcript), all labelled in the
  output.

## 6. Limitations

- Deterministic replay of recorded candidates — **not** a live-model evaluation.
  R measures recording fidelity of the extraction/decision logic given a known
  candidate; it does not measure model quality.
- Single real de-identified Session (S9); **not** a multi-Session trajectory. C
  and S are N/A here by construction.
- Turn-3 is a recorded `provider_incomplete` failure; its R is assessed on the
  fallback pending snapshot only.
- R = 100% here reflects that the recorded candidate was already faithful; the
  negative controls show the same runner scores lower on faulty candidates, so the
  100% is a measurement, not a tautology.
- Database audit and authenticated application acceptance were not run (out of B1
  scope); they remain pending.
